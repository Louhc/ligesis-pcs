LIGESIS / DLIGESIS DATA FLOW (GRID VIEW)
=======================================

Legend:
- base_mu = DeepFold chunk size (low variables)
- chunk index b corresponds to high variables
- col hash = hash(column) -> Merkle leaf

1) Chunking view (evals -> chunks)
----------------------------------
Evals arranged as a 2D grid:
rows = chunk index b (high vars), cols = low index (x_low)

        x_low ->
      +------+------+------+------+
 b=0  | f0   | f0   | f0   | f0   |
      +------+------+------+------+
 b=1  | f1   | f1   | f1   | f1   |
      +------+------+------+------+
 b=2  | f2   | f2   | f2   | f2   |
      +------+------+------+------+
 b=3  | f3   | f3   | f3   | f3   |
      +------+------+------+------+

Each row is one chunk f_b(x_low) with 2^base_mu evaluations.
Combine at open/verify:
  f(x_low, x_high) = sum_b f_b(x_low) * eq(b, x_high)

2) LigeSIS commit data flow (matrix view)
-----------------------------------------
F (m x n)  --RS encode-->  F' (m x 2n)  --SIS hash-->  H (c x 2n)

F (m x n)            F' (m x 2n)                 H (c x 2n)
+----+----+          +----+----+----+----+       +----+----+----+----+
| f  | f  |          | f' | f' | f' | f' |       | h  | h  | h  | h  |
| .. | .. |   ==>    | .. | .. | .. | .. |  ==>  | .. | .. | .. | .. |
| f  | f  |          | f' | f' | f' | f' |       | h  | h  | h  | h  |
+----+----+          +----+----+----+----+       +----+----+----+----+

Then commit H via chunked_batch_commit (H may be chunked by base_mu).

3) Batch commit (column-hash) Merkle tree
-----------------------------------------
v0_matrix (rows = polys/chunks, cols = positions)

      col0  col1  col2  col3
     +-----+-----+-----+-----+
row0 |  v  |  v  |  v  |  v  |
     +-----+-----+-----+-----+
row1 |  v  |  v  |  v  |  v  |
     +-----+-----+-----+-----+
row2 |  v  |  v  |  v  |  v  |
     +-----+-----+-----+-----+

Hash each column to a Merkle leaf:
  leaf0 = hash(col0)
  leaf1 = hash(col1)
  leaf2 = hash(col2)
  leaf3 = hash(col3)

Merkle tree (binary example):
  leaf0  leaf1  leaf2  leaf3
    \     /       \     /
     h01           h23
        \         /
             root

4) DeepFold single-poly Merkle (leaf grouping by stride)
--------------------------------------------------------
FFT output v0 is grouped by LEAF_SIZE with stride = len/leaf_size.
Each leaf contains a vertical slice:

v0 indices (stride grouping):
  leaf0 = [v0[0], v0[step], v0[2*step], ...]
  leaf1 = [v0[1], v0[1+step], v0[1+2*step], ...]
  ...
Then hash(leaf_i) -> Merkle tree -> rt0.

5) Distributed column-hash Merkle (d_chunked_batch_commit / d_commit_v2)
------------------------------------------------------------------------
Columns are partitioned across workers:

v0_matrix columns:
+----+----+----+----+----+----+----+----+
| c0 | c1 | c2 | c3 | c4 | c5 | c6 | c7 |
+----+----+----+----+----+----+----+----+
  |    |    |    |    |    |    |    |
  |    +----+----+----+    +----+----+----+
  |         worker0              worker1

Each worker:
  - receives its column block
  - hashes columns -> local leaves
  - builds local Merkle tree -> local root
Master:
  - gathers local roots
  - builds upper tree -> global root

6) Distributed chunked open data flow (grid intuition)
------------------------------------------------------
local evals -> (gather if needed) -> SumCheck -> r
r_low = r[0..base_mu) used to eval all chunks
chunk_evals_at_r_low -> batch_open -> distributed Merkle proofs
master aggregates proofs -> final LigeSISProof
